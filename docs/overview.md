# MemoReader 개요

## 목적

웹/SNS를 보다가 참고할 만한 링크나 글을 **복사·붙여넣기 또는 공유**로 저장하면, 자동으로 분류·정리(요약, 태그, 카테고리)하고 **원문을 함께 보관**해 나중에 보기 좋게 만들어 주는 개인용 앱.

## 주 사용 패턴

- **입력은 주로 모바일** (공유 버튼, 붙여넣기, 텔레그램 봇), **정리는 PC**(링크 본문 수집 + LLM), **보기는 모바일·PC 모두**
- 따라서 폰은 "빠르고 확실하게 저장 + 정리된 결과 열람", PC는 "정리 처리 + 편집·검색·관리"에 최적화

## 요구사항

| # | 요구사항 |
|---|----------|
| R-01 | 모바일에서 저장 가능 (공유 버튼, 붙여넣기, 텔레그램 봇) |
| R-02 | 정리된 결과는 모바일·PC 모두에서 확인 가능 |
| R-03 | 저장 시 원문 보존 + LLM으로 제목·요약·태그·카테고리 자동 생성 |
| R-04 | 구조는 SNS-Reader(`C:\Claude\SNS-Reader`), UI는 SongYUE2(`C:\Claude\SongYUE2\app`)를 참고 |

## 확정된 결정 (2026-10-12)

| 항목 | 결정 | 이유 |
|------|------|------|
| 저장 입구 | 전용 앱(PWA) + 텔레그램 봇 둘 다 | PWA는 공유 시트·UI, 봇은 가장 빠른 보조 입구 |
| 데이터 위치 | PC 서버 + 외부접속 터널 | 무료, 원문이 내 PC에 남음 (SNS-Reader와 동일 철학) |
| 정리 방식 | LLM 자동 정리 | SNS-Reader의 enrich 방식 재사용 |
| 카카오톡 | 제외 | 개인용 봇/공유 API가 사실상 없음 |

## 처리 흐름

```text
메모 입력 (모바일/PC/텔레그램)
  → 이 기기에 즉시 저장 (원문 보존, 상태: 정리 대기)
  → PC 서버로 동기화
  → 링크 본문 가져오기 (제목·설명·대표 이미지·본문 텍스트)
  → LLM: 간단 요약 + 태그 + 카테고리 선정 (기존 카테고리 우선 재사용)
  → 카테고리 폴더로 이동 (items/<카테고리>/<id>.md, 정리 전은 items/_inbox/)
  → DB(Markdown) 저장: 제목 · 요약 · 원문 · 링크 · 태그
  → 모든 기기로 결과 동기화
```

- 카테고리가 `네트워크/DNS`처럼 `/`를 포함하면 하위 폴더로 저장 (최대 3단계)
- 카테고리를 편집하면 파일도 해당 폴더로 따라 이동
- LLM이 실패해도 항목은 `정리 실패`로 남고, 원문은 그대로이며 "다시 정리"로 재시도

## PC가 항상 켜져 있지 않을 때 (저녁에만 켜는 경우)

- **자동 시작:** `scripts\autostart-install.bat`을 실행하면 로그인 30초 뒤 `start.bat`이 자동 실행된다 (`autostart-remove.bat`로 해제). `tailscale serve --bg`의 설정은 재부팅 후에도 유지된다.
- **밀린 메모 처리:** 서버가 뜨면 대기 중이던 항목을 순서대로 정리한다. 정리가 끝난 항목은 대기열에서 빠지고(상태 `정리 완료`), 폰에 동기화된다.
- **LLM 미설정으로 실패했던 항목:** 설정에서 LLM을 고르면 자동으로 다시 정리한다. 모델 응답 오류로 실패한 항목은 자동 재시도하지 않고 "다시 정리"로 직접 재시도한다.
- **텔레그램:** PC가 꺼져 있는 동안 보낸 메시지는 텔레그램 서버에 남아(약 24시간) PC가 켜지면 한꺼번에 받아 오며, 저장 시각은 메시지를 보낸 시각으로 기록된다.
- **폰에 쌓인 메모 (푸시로 깨우기):** 폰이 설정에서 알림을 켜 두면 PC 서버가 뜬 15초 뒤 폰에 푸시를 보낸다. 폰의 서비스 워커가 앱이 닫혀 있어도 깨어나 쌓인 메모를 PC로 올리고 결과를 받는다(PC에 닿지 않으면 4초·10초 뒤 재시도, 그래도 안 되면 "눌러서 앱을 열면 다시 시도" 알림). PC가 정리를 마치면 한 번 더(여러 건은 20초간 묶어서 1회) 푸시를 보내 정리된 최종 내용을 폰이 받아 간다. 알림은 항상 같은 자리(tag)에서 갱신된다.
  - 푸시 본문에는 메모 내용이 없고 종류와 개수만 담긴다.
  - 필요 조건: 폰이 알림 권한을 허용, 폰의 Tailscale이 켜져 있음(안드로이드는 상시 VPN 권장), PC가 인터넷에 연결되어 푸시 서비스(FCM/Apple/Mozilla)에 접근 가능.
  - 폰 앱을 직접 열면 푸시 없이도 즉시 동기화된다.

## 저장 구조 (PC 서버, `data/`)

```text
data/
  vault_output/              ← Obsidian 보관소로 열 수 있는 최상위 폴더 (VAULT_DIR로 변경 가능)
    _inbox/                  정리 전/카테고리 없음
    웹 개발/제목 (id).md
    네트워크/DNS/제목 (id).md
  tombstones.json            삭제 기록 (동기화용, 보관소 밖)
  runtime/settings.json      LLM·텔레그램·접근 설정 (비밀값 포함, gitignore, 보관소 밖)
```

각 `.md`는 frontmatter(id, 상태, url, 제목, 요약, 카테고리, 태그 등) + 제목·링크·대표 이미지 + `## 요약` + `## 원문` + `## 링크 본문`. 자세한 내용과 주의점은 [obsidian.md](obsidian.md).

## 태그와 같은 링크의 합치기

- 태그는 정리할 때 10개 안팎(설정에서 변경)으로 붙으며 Obsidian 태그 규칙에 맞게 저장된다 (`예약 도메인` → `예약-도메인`).
- 같은 링크를 다른 경로(폰, 텔레그램, PC)로 저장하면 하나로 합쳐진다. 먼저 저장된 시각과 정리 결과를 남기고, 원문은 둘 다 보존(다르면 구분선으로 이어 붙임)하고, 태그는 합치고, 즐겨찾기는 하나라도 있으면 유지한다. 다른 기기의 중복본은 다음 동기화 때 사라진다.

## 화면 구성

**PC (창 폭 1000px 이상)**
- 왼쪽 사이드바: `보관함(전체 개수)` 아래에 카테고리 트리(펼침/접힘, 하위 카테고리는 `/`로 구분, 상위를 고르면 하위 글까지 표시). 카드를 카테고리에 끌어다 놓으면 그 카테고리로 이동(서버에서도 폴더가 바뀜). 펼침 상태는 기억된다.
- 오른쪽: 상단에 제목·검색(가운데)·보기 전환(카드/리스트/메시), 그 아래 빠른 저장 입력과 필터 칩. 선택한 보기 방식은 기억된다.
- **카드**: 사진·영상 미리보기가 먼저 보이는 보드. **리스트**: 한 줄에 썸네일·제목·카테고리·태그·출처·시각.
- **메시**: SNS Reader 방식. 메모=원, 태그를 공유하는 메모끼리 선으로 연결(공유 태그가 많을수록 굵음), 같은 카테고리는 같은 색, 끌어서 이동·휠로 확대, 글 위치에 맞춰 자동 확대. 오른쪽의 "자주 쓰인 태그"(빈도 막대)를 누르면 그 태그의 연결선만 강조. 이 패널은 창이 좁아져도 항상 오른쪽에 있고 폭과 글자 크기만 줄어든다.
- **정렬 막대** (SongYUE2 방식, 필터 줄 오른쪽): 새로고침(지금 동기화) | 최근 저장 순 · 오래된 순 · 제목 가나다순 · 제목 역순 · 즐겨찾기 먼저. 아이콘만 있고 마우스를 올리면 설명이 뜨며 선택한 정렬은 기억된다.
- **카테고리 정렬** (사이드바 `보관함` 아래 작은 막대): 메모 많은 순 · 이름 가나다순 · 최근 저장 순. 하위 카테고리에도 같은 순서가 적용되고 선택은 기억된다. 폰의 카테고리 선택 메뉴도 이 순서를 따른다.
- **정리 실패 다시 정리**: 정리에 실패한 메모가 있으면 필터 줄에 `정리 실패 N` 칩(그것만 모아 보기)과 주황색 `실패한 N개 다시 정리` 버튼이 나타난다. 버튼은 **실패한 메모만** 대기열에 넣고(정상 메모는 건드리지 않음) PC가 한 건씩 차례로 처리한다. 폰에서는 `정리 실패` 칩을 켜면 같은 버튼이 나타난다. 설정이 비어서 실패한 것은 설정을 고치면 자동으로 다시 정리된다.
- **떠오르는 효과**: 마우스를 올린 카드는 위로 3px 살짝 떠오르며 그림자가 부드럽게 퍼지고 썸네일이 조금 확대된다(기울이거나 뒤틀지 않음). 리스트 행은 1px 떠오르고 그림자만 생긴다. 실제 마우스가 있는 화면에서만 동작하고, 터치 화면이나 OS의 "동작 줄이기" 설정에서는 꺼진다.
- 카드·리스트·메시의 원을 누르면 **팝업**으로 내용이 열린다(Esc·바깥 클릭·X로 닫기). 카드 오른쪽 위와 리스트 오른쪽 끝에 **즐겨찾기·수정·삭제** 아이콘(삭제는 두 번 눌러야 삭제, 수정은 팝업이 편집 상태로 열림).
- 사진·영상 미리보기: 대표 이미지와 본문 사진 갤러리, 영상 파일은 앱 안에서 재생, 유튜브 링크는 썸네일 후 눌러서 재생. 사진·영상 파일 링크를 직접 저장해도 그 파일이 미리보기가 된다.

**폰 (창 폭 1000px 미만)**
- 지금 구조 유지: 상단바, 하단 탭(보관함·저장·설정), 카드 목록 → 누르면 상세 화면.
- 목록 맨 위에 **카테고리 선택 메뉴**(하위는 `└`로 들여쓰기), 그 아래 검색과 필터 칩. 메시·리스트 보기는 없다.

## 동작 모드 (로컬 우선)

| 모드 | 동작 |
|------|------|
| 모바일 단독 | 폰 PWA가 IndexedDB에 저장·조회·검색·편집. PC가 꺼져 있어도 동작. 정리는 "정리 대기"로 두었다가 PC 연동 시 PC가 처리 (폰에서 직접 LLM 호출은 후순위) |
| PC 단독 | PC 서버(Markdown 파일)와 브라우저만으로 동작. 링크 본문 수집·LLM 정리·텔레그램 봇은 PC 서버가 담당 |
| 연동 | 폰이 Tailscale로 PC에 닿으면 양방향 동기화 (PC가 정리한 결과가 폰에 반영, 폰에서 저장한 것이 PC로 반영) |

- 모든 클라이언트(폰, PC 브라우저)는 같은 앱 코드이고 IndexedDB를 1차 저장소로 씀. PC 서버는 동기화 허브이자 영구 보관소
- 동기화: 항목 `updatedAt` 기준 last-writer-wins, 삭제는 tombstone, 항목 ID는 기기에서 생성(충돌 없음)
- 한계: 폰 단독 모드에서는 브라우저 CORS 때문에 링크 본문을 가져올 수 없음 (공유된 텍스트/제목/URL만 보관, 본문 수집은 PC 연동 시)

## 구조 (SNS-Reader 참고)

- React + TypeScript + Vite 프론트엔드, 단일 PWA (모바일·PC 공용 반응형)
- Node 백엔드: 동기화 API, 링크 본문 수집, LLM 정리, 텔레그램 봇
- 저장: 항목별 Markdown(frontmatter + 원문) + 미디어 폴더
- 목록/상세 분리, 카드 목록 가상화 (대용량 대비)
- `shared/`: 서버·클라이언트가 함께 쓰는 ID 생성, URL 정규화, 정리 프롬프트/결과 검증
- 터널(Tailscale)로 폰에서 PC 서버 접속
