# Rules

> 이 프로젝트의 규칙과 컨벤션. 모든 sub-agent가 반드시 따라야 함.

## G-01: 코드 주석은 영어만 사용 (MANDATORY)

**규칙:** 모든 코드 주석(`//`, `/* */`, `///`)은 영어로 작성. 한글 주석 금지.
**이유:** 소스 파일 내 한글은 인코딩 문제 및 빌드 오류를 유발할 수 있음.
**적용 시점:** 코드 작성 또는 수정 시 항상. UI 텍스트(사용자에게 보이는 문자열)는 한국어 유지.

## P-01: 사용자 원문은 절대 가공·삭제하지 않는다

**규칙:** `input`(사용자가 저장한 텍스트)은 정리/재정리/동기화 어디서도 바뀌지 않는다. 정리 결과는 title/summary/category/tags와 `page`(수집한 본문)에만 쓴다.
**이유:** 프로젝트의 핵심 약속이 "원문 포함 보관"이다. LLM 실패 시에도 항목은 `failed` 상태로 남고 재시도 가능해야 한다.
**적용 시점:** organize, sync, store 수정 시 항상.

## P-02: 모든 기기에서 저장·열람은 서버 없이 동작해야 한다

**규칙:** 클라이언트는 IndexedDB를 1차 저장소로 쓰고, 서버 연결은 동기화·정리에만 사용한다. 화면은 로컬 DB만 읽는다.
**이유:** 폰 단독 / PC 단독 / 연동 3가지 모드를 모두 지원해야 한다.
**적용 시점:** 새 화면·기능이 서버 API를 직접 호출하려 할 때 (설정 화면처럼 본질적으로 서버 기능인 경우만 예외).

## P-03: 백엔드는 loopback에만 바인딩한다

**규칙:** `127.0.0.1`에서만 listen, 외부 접근은 `tailscale serve`(같은 PC에서 접속)로만 허용. Tailscale 신원 헤더는 loopback 접속에서만 신뢰하고 Funnel 요청은 거부한다.
**이유:** 헤더 위조 방지와 인터넷 노출 방지.
**적용 시점:** 서버 listen 옵션이나 인증 코드를 바꿀 때. Vite dev 서버도 `host: 127.0.0.1`.

## P-04: 비밀값은 브라우저로 되돌려 보내지 않는다

**규칙:** API 키·봇 토큰은 `hasApiKey` 같은 boolean으로만 응답하고, 빈 입력은 "기존 값 유지"로 처리한다. 설정 파일은 `data/runtime/`(gitignore).
**적용 시점:** 설정 API 수정 시.

## P-06: 푸시 구독 endpoint는 허용 목록에서만 받는다

**규칙:** 클라이언트가 보낸 push endpoint로 서버가 요청을 보내므로 FCM/Mozilla/Apple/Windows 푸시 도메인이 아니면 거부한다. 푸시 본문에는 메모 내용을 넣지 않는다(종류·개수만).
**적용 시점:** `backend/push.mjs`를 수정할 때.

## P-07: 서비스 워커에서 쓰는 코드는 DOM/`window`에 의존하지 않는다

**규칙:** `src/sw.ts`가 import하는 모듈은 `tsconfig.sw.json`(WebWorker lib)으로도 타입체크되어야 한다. 공용 상수·로직은 `syncCore.ts`처럼 UI 없는 모듈에 둔다.
**이유:** DOM 의존 모듈을 import하면 워커 번들에 UI 코드가 딸려 들어가고 타입체크가 깨진다.

## P-08: 보관소(vault) 안에서 앱이 만든 노트만 건드린다

**규칙:** `id` 프런트매터가 있는 노트만 읽고 쓰고 지운다. `.obsidian`, `.trash` 등 점(.) 폴더와 사용자가 직접 쓴 노트는 읽지도 수정하지도 삭제하지도 않는다. 새 파일 이름은 `noteFileName`으로만 만든다.
**이유:** 보관소는 사용자의 Obsidian과 공유된다.

## P-09: PC 툴바와 사이드바는 창이 좁아져도 구조를 바꾸지 않는다

**규칙:** 검색창은 툴바 폭의 비율(%)로 정하고 가운데에 고정, 줄바꿈하지 않는다. 태그 빈도 패널은 항상 오른쪽에 두고 폭·글자만 줄인다. 좁아지면 글자를 숨기고 아이콘만 남기는 식으로 줄인다.
**이유:** 창을 줄였을 때 요소가 아래로 밀려 내려가는 것을 사용자가 원하지 않았다 (요청 사항).

## P-10: 링크 안에 버튼을 넣지 않는다

**규칙:** 카드·행 전체가 링크일 때 즐겨찾기/수정/삭제 같은 버튼은 링크의 형제 요소로 두고 위치만 겹친다.

## P-05: 항목을 바꾸는 모든 경로는 `updatedAt`을 올린다

**규칙:** 로컬 편집은 `nextStamp`, 서버 편집은 `store.update`를 통해서만 수정한다. 파일을 직접 쓰지 않는다.
**이유:** 동기화가 `updatedAt`으로만 변경을 판단한다.
